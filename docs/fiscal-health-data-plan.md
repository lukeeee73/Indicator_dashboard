# 재정 건전성(부채 자산) 데이터 확장 계획

> 목적: "한국과 미국 정부의 재정 상태가 건강한가"를 데이터로 판정하기 위해
> 현재 DB에 무엇이 있고, 무엇이 없고, 무엇을 어떻게 가져와 어떤 식으로
> 계산에 쓸 것인지를 정리한 조사 문서. **구현 전 설계 단계 문서**이며,
> 코드 변경은 포함하지 않는다.
>
> 작성 기준일: 2026-07-26

---

## 0. 요약 (TL;DR)

- 현재 DB에서 "부채/재정"에 해당하는 시계열은 **사실상 1개**(`GFDEGDQ188S`, 미국 연방부채 %GDP)뿐이다.
  한국 재정 데이터는 **0개**다 (`DEBTTLKRQ052N`은 코드에 등록만 되어 있고 실제로는 수집 실패 중).
- 금리는 `DGS10` **1개 만기**만 있다. 만기별 수익률 분포를 볼 수 없다.
- 발행량, 만기구조, 입찰 수요, 보유자 구성, 중앙은행 대차대조표, 외환보유고는 **전부 없다**.
- 재정 건전성의 핵심은 부채의 **크기(stock)** 가 아니라 **감당능력(flow)** 이다.
  즉 `r − g`(실효 조달금리 − 명목성장률)와 `이자지출/세입` 두 개가 최상위 지표이고,
  현재 DB로는 둘 다 계산이 **불가능**하다.
- 한국 데이터는 FRED로 해결이 안 된다. FRED의 OECD MEI 계열이 대거 중단되어
  한국 CPI/산업생산/M2가 이미 죽어 있다. **ECOS(한국은행) OpenAPI + 기획재정부 국채시장**이 필수다.
- 부채 지표는 **추세(trend)** 라서 기존 대시보드의 백분위(percentile) 스코어링이 그대로는 작동하지 않는다.
  (부채비율 백분위는 거의 항상 100에 붙는다.) **임계치 기반 구간 점수 + 변화율**로 별도 설계해야 한다.

## 2. 분석 프레임워크 — 무엇을 계산할 것인가

"재정이 건강한가"는 단일 숫자가 아니라 **5개 축**의 문제다.
데이터 목록을 나열하기 전에, 최종적으로 계산하려는 식을 먼저 고정한다.
(데이터는 이 식의 입력으로 역산해서 고른다.)

### 축 A — 지급능력 (Solvency): 부채가 자기증식하는가

부채 동학의 표준 방정식:

```
Δd_t  =  ( (r − g) / (1 + g) ) × d_{t-1}  −  pb_t

d  : 정부부채 / 명목GDP
r  : 실효 조달금리 (실제로 지불 중인 평균 이자율, 명목)
g  : 명목 GDP 성장률
pb : 기초재정수지(primary balance) / GDP  = (재정수지 + 이자지출) / GDP
```

**핵심 판정**: `r − g > 0` 이면 기초재정흑자(`pb > 0`) 없이는 부채비율이 **자동으로 발산**한다.
반대로 `r − g < 0` 이면 적자를 내면서도 부채비율은 하락할 수 있다.
2010년대 미국·한국은 `r − g < 0` 이었고, 2022년 이후 미국은 `r − g`가 0 근처로 올라왔다.
이 부호 전환이 "재정 건전성"에서 가장 중요한 단일 사건이다.

→ 필요한 입력: `d`(부채/GDP), `r`(**평균 이자율 — 시장금리가 아니라 실제 지불 이자율**),
`g`(명목 GDP), `pb`(기초재정수지). **현재 DB로는 `d` 하나만 있다.**

### 축 B — 감당능력 (Affordability): 세금으로 이자를 낼 수 있는가

```
이자부담률 = 순이자지출 / 정부 세입
```

신용평가사가 실제로 보는 숫자다. 경험적 임계:
- < 5% : 건강
- 5~10% : 주의
- 10~14% : 경고 (미국이 2024~2026년 이 구간에 진입)
- > 14% : 위험

부채/GDP 는 200%여도(일본) 금리가 0이면 문제가 없고,
60%여도 금리가 15%면 파산한다. **비율보다 흐름이 먼저다.**

### 축 C — 구조 (Structure): 언제, 누구에게 갚아야 하는가

```
롤오버 리스크 = (1년 내 만기도래 원금 + 당해 신규 적자) / 명목GDP
WAM (가중평균만기)
단기물(T-bill) 비중 = bills / 총 시장성 국채
외국인 보유 비중 = 외국인 보유액 / 총 시장성 국채
```

만기가 짧을수록 금리 상승이 즉시 이자비용으로 전이된다(금리 재설정 속도).
외국인 비중이 높을수록 외부 충격에 취약하다.
미 재무부의 T-bill 비중 관리 목표는 대략 15~20%이며, 이를 넘어가면 단기조달 의존 신호다.

### 축 D — 수요 (Demand): 시장이 받아주는가

```
입찰 응찰률(bid-to-cover) 3개월 이동평균 및 그 z-score
Indirect bidder 배분 비율   (외국 중앙은행 수요의 대리변수)
Tail = 낙찰금리 − 발행 직전(when-issued) 금리   (양수·확대 = 수요 약화)
텀 프리미엄 (term premium)
```

**축 A·B가 "펀더멘털"이라면 축 D는 "시장의 채점표"다.**
재정 위기는 부채비율이 어떤 숫자를 넘어서 오는 게 아니라,
**입찰이 안 되기 시작할 때** 온다 (2022년 영국 gilt, 2023년 10월 미 장기물).

### 축 E — 완충 (Buffer): 터졌을 때 막을 수 있는가

- 미국: 기축통화 프리미엄 자체가 완충. 대리변수는 달러지수 + 외국인 수요 + Fed의 흡수 여력.
- 한국: **외환보유고가 곧 완충장치**.
  ```
  Guidotti–Greenspan 룰: 외환보유액 / 단기외채(잔존만기 1년) ≥ 1.0
  보유액 / M2   (자본유출 방어력, 신흥국 기준 대략 ≥ 20%)
  보유액 / GDP
  순대외금융자산(NIIP)  — 한국은 순채권국이라 이게 큰 강점
  ```
- 중앙은행 자체의 부채도 봐야 한다:
  - 미국: 지급준비금 + 역레포(RRP) + TGA = Fed의 부채. Fed 손실(이연자산)도 재정 이슈.
  - 한국: **통화안정증권(통안채) 발행잔액** — 한국은행의 이자 지급 부채이며,
    국가채무 통계에는 안 잡히지만 실질적으로 공적 부채다. 한국 특유의 항목이라 반드시 필요.

## 3. 추가로 가져와야 할 데이터 — 미국

### 3.1 만기별 수익률 곡선 (FRED, 일간, 무료 API 키)

| 시리즈 | 만기 | 비고 |
|---|---|---|
| `DGS1MO` `DGS3MO` `DGS6MO` `DGS1` | 단기 | 정책금리 경로 반영 |
| `DGS2` `DGS3` `DGS5` `DGS7` | 중기 | |
| `DGS10` (보유) `DGS20` `DGS30` | 장기 | **재정 리스크가 가장 먼저 반영되는 구간** |
| `DFII5` `DFII10` `DFII30` | TIPS 실질금리 | 명목−실질 = BEI 분해 |
| `T10Y3M` | 10Y−3M | NY Fed 침체확률 모델의 표준 스프레드 |
| `THREEFYTP10` | 10년 텀 프리미엄 | Kim–Wright 모형, 1990~ 일간 |

**왜 필요한가**
- 지금은 `DGS10` 하나뿐이라 "금리가 올랐다"는 것만 알 수 있고, **왜** 올랐는지 분해가 안 된다.
- 커브 전체가 있으면 10년물 상승을 세 가지로 분해할 수 있다:
  1. 단기 구간(1M~2Y)이 같이 올랐다 → **통화정책 기대** (재정과 무관)
  2. 장기만 올랐고 BEI(`DGS10 − DFII10`)가 올랐다 → **인플레이션 우려**
  3. 장기만 올랐고 **실질금리·텀프리미엄**이 올랐다 → **재정 리스크 프리미엄** ← 우리가 찾는 신호
- 이 분해가 없으면 "국채금리 상승"이 좋은 뉴스인지 나쁜 뉴스인지 영원히 알 수 없다.

**계산**
```
BEI(만기 m)        = DGS{m} − DFII{m}
곡률(butterfly)     = 2×DGS5 − DGS2 − DGS10
장기 기울기(5s30s)  = DGS30 − DGS5
재정 프리미엄 대리  = Δ THREEFYTP10  (60일 변화)
베어 스티프닝 판정  = Δ DGS30 > 0  AND  Δ(DGS30 − DGS2) > 0  AND  Δ DFII30 > 0
                     → "성장 기대가 아니라 재정 우려로 장기금리가 오르는 중"
```

**왜 필요한가**
- `GFDEGDQ188S`는 **정부간 부채(사회보장 신탁기금)를 포함**해서 실제 시장이 소화해야 하는
  부채를 과대평가한다. 시장 관점에서는 `FYGFGDQ188S`(공공보유)가 맞는 분모다. 둘 다 보유해야 비교가 된다.
- `MTSDS133FMS`(월간)가 있어야 분기 부채 데이터의 **206일 지연**을 메울 수 있다.
  현재 `GFDEGDQ188S`는 2026-01이 최신 — 반년 전 데이터로 "지금 재정이 건강한가"를 판단하고 있다.
- `A091RC1Q027SBEA / 세입` → 축 B 이자부담률.
- `FDHBFIN / GFDEBTN` → 외국인 의존도. 이 비율의 **하락**이 곧 "외국이 미 국채를 덜 산다"는 신호.
- `GDP`는 `g`(명목성장률) 계산에 필수. 현재 DB에 **명목 GDP가 없다** — 부채동학 계산의 결정적 결손.

| `/v1/accounting/od/interest_expense` | 국가부채 이자비용 | 월간 |
| `/v1/accounting/od/debt_to_penny` | 총부채 (일간) | 일간 |

**왜 필요한가 — 이게 이번 확장에서 가장 중요한 데이터다**

`avg_interest_rates`는 미국이 **실제로 지불하고 있는 평균 이자율**이다.
시장금리(`DGS10`)와는 전혀 다른 숫자다. 예컨대 시장 10년물이 4.5%여도
기존 부채의 평균 이자율은 2016~2021년에 발행된 저금리 채권 때문에 3.3% 수준일 수 있다.
**이 간극(시장금리 − 평균이자율)이 앞으로 몇 년에 걸쳐 이자비용으로 실현될 예약된 손실**이다.

```
r (부채동학의 r)      = avg_interest_rates(Total Marketable)
리프라이싱 압력       = DGS10(현재 시장금리) − r
   → 양수이고 클수록: 만기 도래분이 재발행될 때마다 이자비용이 계단식으로 상승
   → 향후 3년 이자비용 증가분 ≈ 리프라이싱 압력 × (3년 내 만기도래 부채)
```

`mspd_table_3_market`으로는 만기구조를 직접 만든다:
```
T-bill 비중 = Bills 잔액 / 시장성 국채 총액        (목표 15~20%, 초과 시 단기의존 경고)
WAM ≈ Σ (각 증권 잔존만기 × 잔액) / 총잔액
1년내 만기도래 비중
```

### 3.4 입찰 수요 (TreasuryDirect / Fiscal Data — 키 불필요)

| 소스 | 내용 |
|---|---|
| `https://www.treasurydirect.gov/TA_WS/securities/auctioned?format=json` | 개별 입찰 결과: `bidToCoverRatio`, `highYield`, `indirectBidderAccepted`, `directBidderAccepted`, `primaryDealerAccepted`, `offeringAmount`, `securityTerm`, `auctionDate` |
| Fiscal Data `Treasury Securities Auctions Data` 데이터셋 | 동일 데이터의 정제 버전 |

**왜 필요한가**
축 D의 핵심. 부채비율은 천천히 움직이지만 **수요는 한 달 만에 무너진다.**
2023년 8~10월 미 장기물 급등의 실시간 신호는 부채비율이 아니라
30년물 입찰의 응찰률 하락 + tail 확대였다.

**계산**
```
만기별 응찰률 z-score:
  BTC_z(m, t) = ( BTC(m,t) − mean(BTC(m, 최근 2년)) ) / std(BTC(m, 최근 2년))
  → 만기(2Y/5Y/10Y/30Y)별로 따로 계산해야 한다. 만기마다 응찰률 수준이 구조적으로 다르다.

외국 수요 대리:
  indirect_share(m,t) = indirectBidderAccepted / (indirect + direct + primaryDealer)
  → 12개월 이동평균 대비 편차

수요 스트레스 신호 (사전 등록):
  최근 3회 입찰의 BTC_z 평균 < −1.0  AND  indirect_share 12MA 하회
  → "수요 약화" 플래그
```

> 스키마 주의: 입찰 결과는 (날짜, 만기, 6개 필드)의 **다차원 데이터**라
> `observations(series_code, observed_at, value)`에 그대로 못 들어간다.
> 원본은 `documents(kind='us_auction', key=CUSIP)`에 JSONB로 저장하고,
> 파생 스칼라(`AUCT_BTC_10Y`, `AUCT_INDIRECT_10Y` 등)만 `observations`로 승격하는 게 맞다.

## 5. 파생 지표 정의 (대시보드에 표시할 최종 계산식)

### 5.1 최상위 4개 헤드라인 지표

| # | 지표 | 계산식 | 데이터 출처 | 임계 |
|---|---|---|---|---|
| 1 | **r − g** | `avg_interest_rate(Total Marketable) − 명목GDP YoY` | FiscalData + FRED `GDP` | `> 0` 전환 = 구조적 악화 |
| 2 | **이자부담률** | `이자지출 / 세입` (12개월 롤링) | `A091RC1Q027SBEA` 또는 MTS table 5 | 10% 주의 / 14% 위험 |
| 3 | **리프라이싱 압력** | `DGS10 − avg_interest_rate` | FRED + FiscalData | 양수 클수록 미래 이자비용 예약 |
| 4 | **수요 스트레스** | `BTC_z 3회 평균` + `indirect_share 편차` + `Δ텀프리미엄` | TreasuryDirect + `THREEFYTP10` | 3개 중 2개 악화 = 경고 |

### 5.2 재정 건전성 종합 점수 (0~100, 높을수록 건강)

**중요 — 기존 백분위 방식을 그대로 쓰면 안 된다.**
현 대시보드는 `_percentile_rank()`로 "역사 분포 안에서 몇 번째인가"를 계산한다.
그런데 부채비율은 단조 증가 추세라 백분위가 **항상 99~100**에 붙고,
"항상 최악"이라는 정보량 0인 신호만 나온다. 성장/인플레는 순환하지만 부채는 순환하지 않는다.

대신 **사전 등록된 임계치 기반 구간 점수(piecewise linear) + 변화율**을 쓴다:

```
S_A (지급능력, 가중 0.30)
    수준점수 : d(부채/GDP)  →  60%↓=100, 60~90%=100→70, 90~120%=70→40, 120%↑=40→0 선형보간
    궤적점수 : Δd(3년)      →  −5%p↓=100, 0%p=60, +10%p↑=0
    발산점수 : (r−g)        →  −2%↓=100, 0%=50, +2%↑=0
    S_A = 0.4×수준 + 0.3×궤적 + 0.3×발산

S_B (감당능력, 가중 0.30)
    이자/세입 → 5%↓=100, 10%=60, 14%=30, 20%↑=0
    리프라이싱 압력 → 0%↓=100, +1.5%p=50, +3%p↑=0
    S_B = 0.6×이자부담 + 0.4×리프라이싱

S_C (구조, 가중 0.15)
    WAM        → 7년↑=100, 5년=60, 3년↓=0
    bill 비중  → 15%↓=100, 20%=60, 30%↑=0
    외국인 비중 변화(2년) → 상승=100, 횡보=60, 하락=0
    S_C = 균등 평균

S_D (수요, 가중 0.15)
    BTC_z (만기별 평균) → +1=100, 0=60, −1.5↓=0
    indirect_share 편차 → 동일 방식
    텀프리미엄 60일 변화 → 하락=100, 0=60, +0.5%p↑=0
    S_D = 균등 평균

S_E (완충, 가중 0.10)
    미국: DTWEXBGS 백분위 + 외국인 순매수 추세
    한국: Guidotti 비율(1.0=60, 2.0↑=100, 0.7↓=0) + 보유고/M2 + NIIP/GDP

재정건전성 점수 = 0.30 S_A + 0.30 S_B + 0.15 S_C + 0.15 S_D + 0.10 S_E
라벨: ≥70 건강 / 40~70 주의 / <40 위험
```

> 임계치는 **모두 사전 등록(pre-registered)** 이며, 결과를 보고 조정하지 않는다.
> 이는 기존 `compare_models.py`의 과적합 방지 원칙과 동일하다.

### 5.3 조기 경보 신호 (백테스트 대상)

```
FISCAL_STRESS 플래그 = 아래 4개 중 2개 이상이 동시 성립:
  (1) Δ THREEFYTP10 (60일) > +0.30%p
  (2) BTC_z (최근 3회 평균) < −1.0
  (3) Δ (DGS30 − DGS2) > +0.40%p  AND  Δ DFII30 > 0   [실질 베어 스티프닝]
  (4) Δ indirect_share (6개월) < −5%p
```

**사전 등록할 정답지(label)** — `data/labels/fiscal_stress_episodes.json` 신설:

| 시기 | 사건 |
|---|---|
| 2011-08 | S&P 미국 신용등급 강등 |
| 2013-05~09 | Taper tantrum |
| 2020-03 | 코로나 국채시장 기능부전 |
| 2022-09~10 | 영국 gilt 위기 (해외 사례, 참조용) / 한국 레고랜드 사태 |
| 2023-08~10 | Fitch 강등 + 장기물 급등 |

한국: 1997-11, 2008-09~2009-03, 2022-09~11.
표본이 5~8개로 매우 적으므로 **성능 수치를 과신하지 말고, 히트/미스만 정성적으로 확인**한다.
기존 4분면 모델(침체 4/4)과 달리 통계적 유의성을 주장할 수 있는 수준이 아니다.

## 6. 수집 파이프라인 설계

### 6.1 신규 스크립트

| 파일 | 소스 | 주기 |
|---|---|---|
| `scripts/fetch_fiscal_us.py` | FiscalData API + TreasuryDirect + TIC CSV | 일/월 |
| `scripts/fetch_ecos.py` | 한국은행 ECOS OpenAPI | 일/월 |
| `scripts/fetch_ktb.py` | 기재부 국채시장 + 열린재정 + 공공데이터포털 | 월 |
| `scripts/analyze_fiscal.py` | §5 파생지표·점수 계산 | 매 수집 후 |

기존 `fetch_fred.py`의 `INDICATORS` 딕셔너리에는 §3.1~3.2, §4.3의 FRED 시리즈만 추가하고,
`category: "fiscal"`, `exclude_assessment: True`로 등록한다
(4분면 성장/인플레 점수를 오염시키지 않기 위해).

### 6.2 스키마 영향

- `series.category`에는 CHECK 제약이 없으므로 `'fiscal'` 값을 바로 쓸 수 있다.
  (`kind`에만 CHECK가 있고 `'indicator'`로 충분하다.)
- **다차원 데이터(입찰 결과, 만기구조 테이블)는 `observations`에 넣지 않는다.**
  `documents(kind, key, payload)`를 사용:
  - `kind='us_auction'`, `key=CUSIP`
  - `kind='kr_auction'`, `key='YYYY-MM-DD-만기'`
  - `kind='mspd_maturity'`, `key='YYYY-MM'`
  파생 스칼라만 `observations`로 승격 (`AUCT_BTC_10Y`, `US_WAM`, `US_BILL_SHARE` 등).
- 만기별 금리는 **각각 별도 `series_code`**로 넣는다 (`DGS2`, `KTB_3Y` …). 가장 단순하고 기존 차트 로직 재사용 가능.
- 예상 증가량: 커브 11개 × 일간 × 60년 ≈ 150k행, 나머지 월간 계열 ≈ 20k행.
  현재 467k행 → 약 640k행. Supabase 무료 티어에서 문제없다.

### 6.3 API 키 / Secrets

| 키 | 필요 여부 |
|---|---|
| `FRED_API_KEY` | 이미 있음 |
| FiscalData | **불필요** (공개 REST) |
| TreasuryDirect | **불필요** |
| TIC | **불필요** (CSV 직접 다운로드) |
| `ECOS_API_KEY` | **신규 발급 필요** (한국은행, 무료, 일 10만 건) |
| 공공데이터포털 키 | 국고채 입찰결과를 API로 받을 경우 필요 (파일 다운로드면 불필요) |

> **주의**: 현재 개발 컨테이너의 egress 정책이 `fred.stlouisfed.org`,
> `api.fiscaldata.treasury.gov`, `treasurydirect.gov`, `ecos.bok.or.kr`를 모두 403으로 차단한다.
> 실제 수집은 GitHub Actions 러너에서만 검증 가능하다.

### 6.4 프론트엔드

`index.html`에 이미 `dollar`(달러 가치) 섹터 탭이 US/KR 양쪽에 있다.
선택지 두 가지:
- **(권장)** `fiscal` 섹터를 신설 — "🏛 재정 건전성". 달러 탭은 환율·통화량에 집중시키고,
  부채·발행·수요·완충은 분리한다. 카드 수가 20개를 넘어가므로 한 탭에 몰면 읽을 수 없다.
- 기존 `dollar` 탭 확장 — 변경은 작지만 정보 과밀.

재정 탭 구성 제안:
1. 상단: 재정건전성 점수 게이지 (미국 vs 한국 나란히) + `FISCAL_STRESS` 플래그
2. 헤드라인 4카드: `r−g`, 이자부담률, 리프라이싱 압력, 수요 스트레스
3. 수익률 곡선 차트: 현재 vs 3개월 전 vs 1년 전 (미국/한국 토글)
4. 입찰 수요 차트: 만기별 BTC 시계열 + indirect 비중
5. 보유자 구성 스택 차트 (Fed / 외국인 / 국내민간)
6. 한국 전용: 외환보유고 적정성 3종 + 통안채 잔액

## 7. 우선순위 (단계별)

### 1단계 — 이걸 안 하면 아무것도 계산 안 됨 (1주)
1. FRED 명목 `GDP` 추가 ← **`g`가 없어서 부채동학 자체가 불가능**
2. FiscalData `avg_interest_rates` ← **`r`**
3. FRED `MTSDS133FMS` (월간 재정수지), `A091RC1Q027SBEA` (이자지출)
4. FRED 수익률 곡선 11종 + `DFII10` + `THREEFYTP10`
5. `FYGFGDQ188S` (공공보유 부채 %GDP)
→ 이 시점에 **`r−g`, 이자부담률, 리프라이싱 압력, 커브 분해**가 전부 계산 가능해진다.

### 2단계 — 한국 정상화 (1~2주)
6. ECOS 키 발급 → 국고채 만기별 금리, 외환보유액, 단기외채, M2, 통안채
7. 죽은 OECD MEI 계열 5종을 ECOS로 이관 (`MYAGM2KRM189S`, `KORCPIALLMINMEI`,
   `KORPROINDMISMEI`, `LRUNTTTTKOR156S`, `DEBTTLKRQ052N`)
8. FRED `GGGDTAKRA188N` + `GGGDTPKRA188N` (D2 및 전망)

### 3단계 — 수요·구조 (2~3주)

### 4단계 — 통합·검증 (2주)

## 8. 한계와 주의사항

1. **백테스트 표본이 너무 적다.** 재정 스트레스 에피소드는 40년간 미국 5회, 한국 3회 수준이다.
   기존 4분면 모델처럼 "FPR 7.7%" 같은 수치를 주장하면 안 된다.
   이 축은 **판정기가 아니라 관찰 도구**로 쓰는 것이 정직하다.
2. **부채비율에 마법의 임계값은 없다.** 일본 250%는 멀쩡하고 그리스 130%는 터졌다.
   차이는 통화 주권, 자국통화 표시 비중, 국내 저축률이다.
   그래서 §5.2가 부채 수준에 30%만 배분하고 감당능력·수요에 45%를 준 것이다.
3. **한국과 미국은 같은 척도로 비교할 수 없다.** 미국은 기축통화 발행국이라
   "외환보유고" 개념이 무의미하고, 한국은 통화 주권이 제한적이라 대외 부문이 결정적이다.
   → 두 나라의 점수는 **나란히 표시하되 같은 임계치를 쓰지 않는다** (§5.2의 S_E가 국가별로 다른 이유).
4. **발표 지연.** 분기 부채 데이터는 2~6개월 지연된다. 백테스트 시 기존
   `backtest.py`의 발표 지연 시뮬레이션 방식을 반드시 적용해야 한다.
   특히 `GFDEGDQ188S`는 현재 206일 지연 상태다.
5. **정의 불일치.** 미국 "총부채 vs 공공보유 부채", 한국 "D1/D2/D3"를 섞으면
   국제비교가 전부 무너진다. `series.details` JSONB에 정의를 명시적으로 저장할 것.
